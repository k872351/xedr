# 日志规范与配置分层

> 借鉴 wazuh `docs/ref/modules/logging/configuration.md`（五级日志 + 层级化 tag + plain/json 双格式 + 轮转）与 `etc/internal_options.conf` / `local_internal_options.conf`（默认值 + 本地覆盖）。
> **本文先如实登记现状，再给渐进落地路线**——不假装已经实现，避免后续误判。

---

## 一、现状登记（2026-11-22 实测）

| 组件 | 现状 | 差距 |
|---|---|---|
| Go Agent | `agent/log.go:setupFileLog()`：`log.SetOutput(io.MultiWriter(os.Stdout, f))`，落 `<StateDir>/agent.log`，flags = `LstdFlags\|Lmicroseconds` | 无级别、无 tag、无轮转、无结构化字段；单文件无限增长 |
| Python 后端 | 各模块散用 `print(f"[xxx] ...")`（如 `[config]`、`[correlation]`、`[building_block]`） | 无统一 logger、无级别、无 tag 规范、无 json 格式 |
| 管理台 | 浏览器 console + 页面内 toast，服务端无前端日志汇聚 | — |
| 配置 | 三层已存在（见 §三） | 无集中文档、响应码/成功码未配置化 |

**结论**：日志是「能看」而非「可治理」。当前规模下先补规范与最小改造，不引入重型日志框架。

## 二、目标规范（渐进采纳）

### 2.1 五级日志

| 级别 | 用途 | Agent 现状映射 | 后端现状映射 |
|---|---|---|---|
| `DEBUG` | 诊断细节、采集单条事件、匹配轨迹 | 目前 `log.Printf` 混杂 | `print` 混杂 |
| `INFO` | 生命周期：启动/注册/心跳周期变更/同步 rev 变更 | 已有 | 已有 |
| `WARNING` | 降级但可继续：传感器不可用、单规则解析失败、队列接近上限 | 部分 | 部分 |
| `ERROR` | 单操作失败：心跳失败、命令失败、采集失败 | 已有 | 已有 |
| `CRITICAL` | 需人工介入：凭据被拒、策略验签失败、DB 损坏、发布件被拒 | 部分 | 部分 |

**约定**：
- 生产默认 `INFO`；`DEBUG` 必须可动态开启且不落盘（避免磁盘放大）。
- `ERROR`/`CRITICAL` 必须带可检索的 `code`（见 2.3），便于告警聚合。
- **禁止**在日志里打印密钥、token、完整策略正文含签名、终端上报的个人标识原文。

### 2.2 层级化 tag

采用 `组件:子模块` 两段式，仿 wazuh `wazuh-manager-modulesd:vulnerability-scanner`：

```
agent:heartbeat          agent:sync             agent:slowlane
agent:cmd                agent:memscan          agent:fim
backend:protocol         backend:correlation    backend:risk
backend:rules            backend:esqueue        backend:approval
```

- 现有 `print("[correlation] ...")` / `log.Printf("sysmon ensure...")` 逐步改为带 tag 前缀。
- tag 用**闭集**（新增需登记本文件），避免自由文本导致检索失效。

### 2.3 结构化字段与双格式

- `plain`（默认，人读）：`2026-11-22 17:24:02.123 INFO [agent:heartbeat] agent_id=... rev=42 msg=...`
- `json`（机器读，可选开关）：每行一个 JSON 对象，固定字段：
  `ts, level, tag, code, msg, agent_id, hostname, component, trace_id`（可选字段按模块扩展）。
- 稳定 `code` 示例：`HEARTBEAT_AUTH_REJECTED` / `POLICY_SIG_INVALID` / `SYNC_BUNDLE_REJECTED` / `CMD_RECEIPT_WRITE_FAILED` / `ES_QUEUE_OUTAGE`。
- `trace_id`：一次心跳/一个命令/一条遥测批次共享，用于跨 Agent↔后端串联（当前未实现，列为后续项）。

### 2.4 轮转与保留

| 项 | 目标 |
|---|---|
| 单文件上限 | 10 MB（可配置） |
| 保留份数 | 5 份，按天或大小轮转 |
| 压缩 | 历史文件 gzip |
| 权限 | `0600`（沿用 Agent 现有 `os.OpenFile(..., 0600)`） |
| 落盘目录 | `<StateDir>/logs/`（Agent）、`<DATA_ROOT>/logs/`（后端） |

**Agent 最小改造路线**（不破坏现有 `log.Printf` 调用）：
1. 在 `agent/log.go` 增加基于 `io.Writer` 的轮转 writer（`log.SetOutput` 换成它），保持所有 `log.Printf` 调用不变；
2. 加 `agentLogLevel` 全局 + `shouldLog(level)` 包装，逐步把关键 `log.Printf` 改为带级别调用；
3. `json` 格式作为可选 env 开关（`FORENSIC_LOG_FORMAT=json`）。

**后端最小改造路线**：
1. 新增 `backend/logfmt.py`：`get_logger(tag)` 返回标准库 `logging.Logger` 适配器，默认输出与现有 `print` 格式兼容；
2. 逐步替换高频 `print`（`config.py` / `correlation_engine.py` / `building_block.py` 优先）；
3. 不引入 structlog / loguru 等新依赖（保持 `requirements.txt` 精简）。

> ⚠️ 上述路线是**规范与建议**，本轮未实施代码改造（避免大规模替换引入回归）。登记为后续项。

## 三、配置三层化（现状已具备，固化约定）

| 层 | 文件 / 变量 | 是否提交 | 优先级 | 说明 |
|---|---|---|---|---|
| L1 默认值模板 | `config/*.example.json` | ✅ 提交 | 最低 | 可提交模板，含字段说明与占位值 |
| L2 本机配置 | `config/*.json` | ❌ 不提交 | 中 | 含密钥/密码/连接串，`.gitignore` 排除 |
| L2' 本地覆盖 | `config/*.json.local`（如 `stack_paths.json.local`、`hj_stack.json.local`） | ❌ 不提交 | **高于 L2** | 仅覆盖差异字段，先读覆盖再读基线 |
| L3 环境变量 | `FORENSIC_*`（`FORENSIC_DATA_ROOT` / `FORENSIC_DB_CONFIG` / `FORENSIC_ES_*` / `FORENSIC_AI_*` / `FORENSIC_CORS` / `FORENSIC_CACHE_*` …） | — | **最高** | 部署时注入，覆盖文件内容 |

**实现依据**：
- `backend/config.py:resolve_config_file()`：`config/` 优先，根目录旧文件回退，写入一律进 `config/`。
- `backend/config.py:migrate_root_configs()`：把根目录遗留配置迁入 `config/`。
- `backend/config.py` 中 `DATA_ROOT`、`FORENSIC_RESULTS_DIR`、`FORENSIC_AI_FORCE`、`FORENSIC_AI_API_KEY` 等均为环境变量覆盖点。
- `CONTRIBUTING.md`：明确「只提交 `*.example.json`，本机配置含密钥禁止提交」。

**决策（ADR-012）**：保持现状三层，不引入新配置框架。理由：约定已被 README / 使用手册 / CONTRIBUTING 覆盖，换框架收益低于迁移风险。

### 3.1 新增配置项约定

- 新增配置**必须**同时补 `*.example.json` 模板字段与默认值。
- 敏感项（密钥、口令、token）只能出现在 L2/L3，模板里用 `""` 或 `<set-me>` 占位。
- 环境变量命名统一 `FORENSIC_<模块>_<语义>`；读取统一走 `backend/config.py`，不要在业务模块里散读 `os.getenv`。
- 响应码/成功码配置化（借鉴 DataProtector `.env`）：当前散落在代码里，若后续抽到 `config/response_codes.json`，须同步更新本文件。

## 四、禁止事项

1. 不删除/改写已有日志中的 `[tag]` 前缀（诊断脚本可能依赖）。
2. 不在日志输出完整 `detail` JSON（可能很大且含敏感字段），用 `code` + 关键字段代替。
3. 不因为加日志把快车道（心跳主循环）变成同步 I/O 热点——日志写入必须异步或有界缓冲（ADR-005）。
4. 不把 `*.json` / `*.json.local` 提交进版本库。
